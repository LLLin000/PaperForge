## 1. Executive reconciliation

The #65 control-center map and the #135 Python-authority map agree on **every domain invariant** — independent module capability states instead of global `setup_complete`; backend-owned facts, severity, and actions; "stale is never ready"; durable per-paper OCR metadata and SQLite truth with JSON as cache; actionable-only maintenance; source preservation on destructive ops; reviewed, redacted, never-auto-submitted issue drafts. #135 does not reverse any of these.

What #135 supersedes is **mechanism, ownership, and schedule** — the plugin-side machinery the #65 map prescribed to deliver those invariants:

1. **Plugin-managed runtime** (#70/#73) → **bootstrap adapter + Python-owned setup/update/repair** (#135 notes; #156). The plugin keeps pre-runtime interpreter discovery and a consented one-time install only. The #70 immutable multi-slot/keep-2/rollback design is **migration evidence**, not a promised target: #156 keeps only a handoff pointer now and defers Python-side slots until an observed need.
2. **Obsidian SecretStorage as credential owner** (#73 §2.6, SG gates) → **Python keyring provider, OS keyring preferred, env support, no plaintext fallback** (#135 notes; #141). Migration mechanics (copy → readback-verify → delete) are retained but the target store and owner change. The headless-CLI `.env` path is **not** retained as settled — its status is owned by #138 (U3).
3. **Versioned JSON snapshots + plugin TTL gates** (#66 §5.1, #69 §9, #73 §2.4) → **snapshots deleted after consumer cutover; one display-only last-known CLI response per module in `data.json`, no semantic TTL/SWR machinery** (#135 notes; #157). The "stale is never ready" invariant survives as fresh-response action gating. The envelope's `ttl_seconds` and `action.command` **fields** are superseded; the wire shape is **migration-dependent** pending #140/#154.
4. **TS action allowlists + command strings** (#66 §9, #69 §5) → **Python action registry with stable `action_id`s and `paperforge action run <action_id> --json`** (#135 notes; #154). Legacy `ALLOWED_ACTIONS` argv tables are migration source, not target.
5. **Plugin config/path parsing and path mirrors** (#66 §2.3, #73 §2.1) → **one Python read/validate/write contract; plugin stops parsing `paperforge.json` entirely; `data.json` holds UI preferences and last-known display state only** (#135 notes; #153).
6. **Blanket three-release dual-authority schedule** (#73 §1) → **#135 vertical clean cutovers** supersede it: one authority per capability per slice; compatibility inside a slice only with explicit expiry, never parallel semantic owners (D21).

**Retained without change:** every #73 accessibility gate (AG-01…AG-12), the macOS-signing and Flatpak/Snap platform gates, redaction/diagnostic privacy rules (SG-01…SG-10 modulo the credential-store swap), Python 3.11+ for new/repair, `paperforge.json` config authority and the v1→v2 vault_config migration direction, per-paper OCR recovery semantics, SQLite `build_state`/schema-migration ownership, the envelope's semantic axes / reason-code grammar / severity mapping / one-primary-action rule (but not its TTL and command fields, and not its wire shape), and the accepted-interim plugin subprocess executor with #150's real-host cancellation evidence.

**Migration-dependent (behavior valid, execution moves):** snapshot freshness gating moves from plugin snapshot-schema checks to CLI-response `received_at` freshness (#157); the SecretStorage copy-verify-delete protocol keeps its shape but the stores it moves between change; setup consolidation and the v1→v2 config cutover keep their staging discipline but under vertical-slice expiry rules; the wire contract moves to #139 NDJSON after cutover.

**Genuinely unresolved:** (U1) auto-sync 120 s mtime-poll trigger ownership — the only new decision fog (no #135 research child resolved the trigger policy). (U3) the headless-CLI `.env`/env credential path — stays with #138, not settled here. (U2) the long-task executor boundary is **resolved**: #150 now carries real Obsidian 1.13.4 evidence (stdin stop → one `cancelled` event → rc130); the plugin subprocess executor remains accepted interim, and daemon/job ownership is deferred/out-of-scope per #135.

## 3. Domain invariants retained unchanged (do not re-litigate)

These are invariant across both maps — any #135-family ticket that contradicts them is wrong:

1. **Module-independent capability states; no global all-or-nothing product state** (D1, D2).
2. **Backend owns facts, severity, reason codes, actions; plugin renders only** (D4, D5, D17) — including maintenance as a backend-derived probe (D9).
3. **Stale is never ready; unknown is not success; freshness gates action enablement** (D7, D8).
4. **`paperforge.json` is the authoritative vault/config owner; Obsidian `data.json` holds UI preferences and display-only last-known state** (D6, D7, D29).
5. **Durable truth stays where it is:** per-paper OCR `meta.json` + version hashes + raw/canonical split; SQLite schema/`build_state`/FTS/vec0/canonical-index hash; `formal-library.json` atomic writes; OCR maintenance SHA256 manifest invalidation (D18).
6. **Maintenance contains actionable items only** — staleness, failed operations, corrupted state with a concrete next action; routine OCR quality scores never enter it (#65 body; D9).
7. **One primary action per module; `ready` → null; `unknown` → probe; stable action vocabulary** (D3, D10).
8. **Destructive ops preserve source materials and require scoped confirmation; two-step for `all`** (D12).
9. **Diagnostics are never auto-submitted; issue drafts are user-reviewed, redacted, no token in URL, no GitHub-token storage** (D23, D30).
10. **Update rollback and PyPI→git fallback survive behind one owner**; cooperative stop between papers (D18, D26).
11. **Offline is per-capability evidence; no global offline flag** (#69 §1; D2 family).
12. **Python 3.11+ for new installs and repairs; 3.10 only as verified-legacy with deprecation** (D15).
13. **macOS auto-download disabled until signed; Flatpak/Snap unsupported initially; unsupported triplets get a manual action** (D24).
14. **Accessibility gates AG-01…AG-12 stand as acceptance criteria** (D22).
15. **Credentials never travel through the runtime manager and never appear in logs/diagnostics/argv** (D16, D23).
16. **Rollback = revert a whole slice; never fall back to the old interpretation at runtime** (#135 notes; D21).
