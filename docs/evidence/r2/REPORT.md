# R2 isolated rebuild — NO-GO

## Decision

**NO-GO.** The full READY acceptance cannot pass against the current R1 plan: the
plan was generated by the replay shortcut (`_new_replay`) while R2 runs the real
`_rebuild_one_paper` pipeline. Their figure IDs and asset claims diverge on most
papers, so plan-vs-actual validation fails systematically. This is a plan/rebuild
parity defect, not a reason to change the frozen Figure algorithm.

No production vault was written. The source vault hashes were unchanged for
every completed batch.

## Coverage

- Selected READY: 788 (from `docs/evidence/r1/papers.json`).
- Processed: 688 papers in 14 completed batches (4 parallel workers).
- Missing: 100 papers because batch-002 of workers 1 and 3 did not finish; no
  result is claimed for them.
- Completed-batch validation: 174 pass / 514 fail.
- Idempotence: file-tree hash equal on 14/14 completed batches.
- Source integrity: unchanged on 14/14 completed batches; no changed keys.

## Failure classes (completed batches)

| Class | Count |
|---|---:|
| `plan_mismatch` | 13,096 |
| `json_parse` (validation scans backup/version JSON) | 1,369 |
| `historical_object_missing` | 14 |
| `historical_text_decrease` | 31 |
| `pending_marker_present` | 1 |

The dominant class is plan mismatch: rebuilt inventories contain IDs/claims that
the R1 plan does not contain, e.g. plan `figure_001_p003_b4` vs rebuilt
`figure_001`, plus renamed/split figure sets. `json_parse` is validation noise
from scanning `backups/` and `versions/` JSON rather than managed structure files.

## Root cause

`scripts/dev/object_migration_dry_run.py::_new_replay` mirrors only part of the
rebuild path (build → pre-match normalize → association → object dry-run). The
real rebuild also runs post-match normalization, full identity finalization,
writebacks and render/health phases. Consequently R1 plan IDs and asset claims
are not the IDs the rebuild actually publishes.

This was exposed only at full READY scale; Dev 50 and the synthetic harness did
not compare plan IDs against real rebuild output.

## What is still valid

- The frozen algorithm's replay, unique-ID and delivery checks remain valid.
- The manifest-only-assets fix and dry-run journal safety fix are valid.
- R2 harness hardening (READY selection, isolation guard, full source hashing,
  historical baseline, plan validation, bounded batches) is valid.

## Required before a GO

1. Generate the migration plan from the **actual rebuild output** (or make
   `_new_replay` execute the same full phase sequence as `_rebuild_one_paper`),
   then regenerate R1 statuses and plan JSONL.
2. Restrict validation JSON parsing to managed `structure/*.json` (exclude
   `backups/`, `versions/`, `.edtz`), and rerun the 100 missing papers.
3. Re-run R2 over all READY papers; only then run R3 visual/acceptance checks.
