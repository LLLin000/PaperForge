## 1. Holistic review findings (all decisions considered)

1. **The plan's Phase 1 is too large for one reviewable diff.** It mixes four independently verifiable units: registry+runner, memory seam, embed seam, reconcile module. Split into T2–T5 below.
2. **Scope-registration rule makes seams verifiable by construction.** T2 registers `memory.build`/`embed.resume` with `scope_kinds=("all",)` only; `papers` registration lands only with the scope-faithful seam (T3/T4). A ticket cannot accidentally ship a non-faithful `papers` scope.
3. **The `unknown` escape hatch is automatic (W1).** Any user-triggered rebuild writes identities: `build_paper_manifest` now always emits `retrieval_identity`; any embed build writes vector lineage rows. `unknown → rebuild → current` works without any auto-rebuild code. Slice 0 adds observation only; no `if unknown: rebuild_everything()` exists anywhere.
4. **Lineage digests are the natural `last_attempt_input_digest`** for the #158 retry rule (W2): reconcile gates re-emission — input digest unchanged AND a failed last attempt recorded on that digest → the repair is not re-emitted (the timer may still re-trigger convergence; gating is Python's). No new `retry_jobs` / `reconcile_history` tables — audit-grep enforced.
5. **#158 resolved (2026-08-09): sync convergence tick.** The Obsidian timer is a dumb client fire into `paperforge sync`: Python detects external source changes (source reconciliation), applies library sync, then runs `reconcile(all)` (derived materialization reconciliation — covers chain breaks even when `changed_keys == []`). Cadence = `data.json` UI preference (`autoSyncEnabled`, `autoSyncIntervalSeconds`); vault-open tick + interval; mtime scanner deleted. `paperforge sync` CLI is the application entrypoint; `library.sync` remains the domain action.
6. **Critical path:** C0 (canonical config authority) → R (read-model cutover, #148) → T1 → T2 → (T3 ∥ T4) → T5 → T6 → T7 → T8 → T9; C0 also feeds C1 (credential authority, parallel with the main chain); F (foundation/bootstrap-client cutover) completes the line, blocked by T9 + C1. R = READ client cutover; T8 = ACTION/TRIGGER client cutover (no duplicate).
7. **Reader gate (immediate correctness) lands with T7**, not later: mismatched/unknown lineage is never served, while reconcile (T5/T6) provides eventual repair.
8. **Old-producer deletion list** (plan §11) is already pinned: `asset_state.compute_next_step`, `compute_health` fix-paths, OCR maintenance `_recommended_action`/`compute_display_fields`, remaining probe/maintenance recommendation producers, TS orchestration, mtime scanner. Net effect targeted: decision code decreases while capability increases.

## 4. Implementation watch items (from design review; tracked here, not re-litigated)

- **W1 — unknown must not deadlock:** probe/reconcile never auto-rebuild on `unknown`; the escape hatch is any user-triggered rebuild (writes identities). Test: legacy vault → `unknown`; after `memory build` → `current`.
- **W2 — not-a-retry:** reconcile gates re-emission: unchanged input digest AND a failed last attempt recorded on that digest → no re-emit (timer may re-trigger convergence; gating is Python's). Reuses existing build/error metadata + lineage digests; no `retry_jobs`, `reconcile_history`, or repair-attempt registry. Audit grep-assert in T9.
- **W3 — single producer:** after T9, materialization-repair recommendations exist only in reconcile; old recommendation code is projection or deleted.

## 5. Wayfinder flow and gates

The map is complete: all decision tickets (#137/#143/#144/#145/#146/#148/#149/#158/#159) are closed and frozen. Completion sequence per [#146](https://github.com/LLLin000/PaperForge/issues/146) (docs/design-implementation-handoff.md): ready-for-agent issues for R + T1–T9 are created via to-tickets and dependency-checked **before** the map closes; then implementation begins, one issue per session (except T3 ∥ T4 parallel).

Gates: slice merge (focused tests + typecheck + Python suite + audit + relevant journey) ≠ integration (alls-green + predecessor contracts) ≠ product release (milestone + wheel/bootstrap smoke + live OCR/embed smoke + Obsidian/browser manual smoke + Windows manual checks). Each slice is whole-slice revertible; no implementation issue may silently widen its frozen design (ambiguity → reopen a planning issue).
