## Purpose and decision rule

This is the single M4 acceptance matrix. Every RC claim must attach a command, artifact, live observation, or owner decision to one row here. M4 is validation, not feature development.

- **BLOCKER:** data loss/corruption, wrong authority, silent fallback, false state, unrecoverable execution, install/upgrade/rollback failure, or broken CLI/machine contract. Fix, then rerun the affected row and all dependent rows.
- **NON-BLOCKER:** cosmetic, ergonomic, performance, or post-RC architecture debt. Record it in the finding log; do not mutate the candidate.
- A row is **PASS** only when the complete path is exercised at the stated boundary. Unit coverage alone is evidence, not live-chain acceptance.
- For every mutation discovered during M4, record: **re-OCR / rebuild / embed requirement + old-user impact**. The default for validation-only work is `none / none / none`.
